The mobile fixture IK adapter changes the robot base and right-arm configuration while retaining every prepared reference row, hand target, object target, gripper intent, and inactive left-arm reference. It is a kinematic planning adapter; it produces no measured observations and makes no claim of physical success.

`mobile_fixture_ik.prepare(prepared, robot, output, *, anchor_index, anchor_reference, base_bounds_xyyaw, minimum_fixture_gap_m=.003)` takes a declared geometric seed and explicit bounds. `anchor_reference` contains planar base x/y/yaw followed by fourteen arm joint angles. The anchor is solved and checked again. The solver follows all original rows backward and forward from that anchor, using constrained SLSQP over the base and seven right-arm joints. A small displacement penalty selects nearby solutions; it does not authorize changing the target pose.

Every solved row is checked against the compiled scene. The aperture envelope comes from the actual declared controller target and calibrated contact angle, with five samples through opening and closing transitions. The inactive gripper remains open. All eligible robot/fixture pairs must maintain the declared positive clearance; only the explicit three wheel/floor support pairs are exempt. The manipulated object's subtree is excluded from fixture checks because grasp contact remains a separate physical gate. Objects remain at the compiled reset state throughout these isolated robot-only FK queries. Predicting other moving task fixtures is not supported by this adapter.

The adapter also requires the existing 2 mm robot penetration, 9 mm self-clearance, 25 mrad joint-margin, and 2 mm / 0.02 rad hand-target criteria. A successful optimizer flag is insufficient: the actual resulting configuration must pass every check. Failed attempts retain numeric solutions, source arrays, constraint diagnostics, and a rejection report. The report binds the scene, external assets, original array dtype/shape/bytes, source metadata, frozen-parent receipt, and output artifact.

Use this adapter before retiming and supported placement. If an approach modifies the free-hand prefix, propose that approach before mobile IK; run the separate approach admission afterward. Retiming requires its own complete interpolation and collision verification, followed by supported placement where the task requires it. Every admitted robot path still needs uninterrupted actuator-only physics, complete recorded states and controls, and independent replay. The original prepared clock is a robot reference clock; it must not be relabeled as a measured native dataset clock.

The first development source is robomimic Can `a60a58d34b6125e76627e883`. A fixed-base screen penetrated the near bin wall by 16.384 mm with the forearm. A bounded mobile/right-arm pose solve showed that the exact target was feasible. The reusable adapter then passed all 731 original rows using the actual `contact_0035` envelope. Adding a 12 cm approach after that fixed mobile trajectory failed IK, so a separate retained retry proposes that approach before mobile planning. These development attempts do not change the original frozen held-out result.

An earlier exploratory full-path script used an aperture offset of **0.002 rad**, although its report called it `contact002`. The named policy `contact_002` actually uses **0.02 rad**. That exploratory artifact is retained with this correction and is not evidence for the named policy. The reusable adapter derives the numeric target from `effective_candidate` and its real pilot uses **0.035 rad** for `contact_0035`.
