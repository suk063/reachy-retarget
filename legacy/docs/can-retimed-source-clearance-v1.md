# Retimed source clearance and repeated approach IK

Seventeen complete placement candidates in `can-mobile-interior-reserve-v1` passed every static check except the unchanged 3 mm robot/fixture clearance. Reading their complete numeric arrays separates two different problems. Thirteen candidates fail only in the retimed original source prefix or suffix; two more have both original-source and inserted-placement failures. The two `a2e2` candidates fail only during inserted lowering and are not interpolation-repair successes.

Every implicated original endpoint has at least 3.001 mm clearance. The failed intermediate references match the recorded linear time-map interpolation within 2.3e-16. All five source manifests have empty passive fixture initialization maps; replaying the isolated planning queries with and without initialization gives identical distances. This cohort is a joint-space chord problem, not a fixture-reset discrepancy. Full candidate/source/phase mappings are retained in `can-retimed-source-gap-audit-v1.json` and `can-retimed-source-fixture-probe-v1.json`.

`retimed_source_clearance.prepare` is an optional stage immediately after `feasible_timing`, before inserted placement. It requires the checksum-bound complete original time map, rejects original-knot deficiencies separately, and modifies only failed derived samples. An existing constrained minimum-motion mobile/right-arm solve retains the interpolated TCP target, object trajectory, gripper intent and clock. Corrections are bounded by 2 mm base XY, 0.01 rad yaw/right-arm joints, both neighboring reference-speed limits and the original joint bounds. The left arm and protected original-clock samples are exact. All original knots and the entire input retimed reference are preserved in the output artifact.

The actual four-source pilot admits all 838, 956, 1,249 and 1,180 reference rows respectively. Maximum required base-coordinate change is 0.1651 mm; maximum right-joint change is 0.000351 rad. Complete FK, fixture, environment, self, joint, scalar speed and planar speed checks pass. Six focused regression tests include protected-knot rejection, partial-failure retention and the 5.44e-15 rad saturated-speed roundoff case; the unchanged final speed threshold still applies. The first `ba7650` roundoff rejection is retained separately. These are geometric repairs, not physical validation; each resulting placement and rollout must still pass independently. Actual pilot records are in `can-retimed-source-repair-pilot-v2.json`.

A separate stage-comparison audit explains the unretimed `710ae7…` and `c59b0e…` failures. Complete mobile IK already admitted their approach targets. The later `grasp_approach.prepare` then re-solves the same prefix with unconstrained right-arm IK, changing the worst-frame joints by about 1.3 mrad. That erases positive clearance: `710ae7` frame 273 changes from at least 3.001 mm to 2.775767 mm; `c59b0e` frame 252 changes to 2.954938 mm. The final checker receives exactly those rewritten references. Both fixture initialization maps are empty. The appropriate opt-in correction is to retain a checksum-bound, completely admitted mobile reference when it already implements the same approach proposal, while still running every existing approach/open-object/full-frame check. The original failure evidence is retained in `can-approach-readmission-difference-v1.json`.

The optional `grasp_approach.prepare(..., preserve_admitted_reference=True)` now verifies the exact checksum-bound preproposal, complete positive-clearance mobile admission, scene, reference, targets, objects, intent and source clock before reuse. It skips only the redundant prefix solve and runs every existing approach/open-object/aperture/full-frame admission check. Both actual sources now pass those checks and the subsequent unchanged 3 mm fixture check with bit-for-bit identical mobile references. Focused tests also ensure stale/incomplete bindings fail and an actual open-hand/object collision remains rejected. This changes neither the default approach behavior nor any physics gate. The two numeric pilot results are retained in `can-approach-reference-reuse-pilot-v1.json`; the source scenes and complete old/new arrays are included in the artifact inventory.
